# Robokassa: разовая лицензия «без рекламы»

Цена зафиксирована на сервере и в проверяемой квитанции: **149.00 RUB**, товар
`ad_free_lifetime`, один платёж, без подписки. Функции дневника остаются бесплатными.
По умолчанию приём платежей выключен. Рабочие учётные данные, URL API, D1 и ключ
подписи владелец задаёт отдельно; наличие этого кода не означает активацию магазина.

## Что входит в интеграцию

Android использует `:robokassa-sdk`, безопасную адаптацию официального
[robokassa/sdk-android](https://github.com/robokassa/sdk-android).
Происхождение, точный upstream commit и изменения: [UPSTREAM.md](../robokassa-sdk/UPSTREAM.md).
Паролей Robokassa и закрытого RSA-ключа в приложении нет. SDK получает подготовленную
сервером POST-форму и показывает Robokassa/3-D Secure; возвращаемый им результат —
только повод проверить заказ, а не доказательство оплаты.

Worker проверяет сумму, invoice, четыре `Shp_*`, режим и подпись ResultURL с Password2.
В live есть дополнительный запрос OpStateExt, если уведомление задержалось: только
после проверки секретного токена заказа, не чаще раза в минуту на заказ. Неоднозначный
ответ провайдера оставляет заказ неподтверждённым. После подтверждения Worker выдаёт
подписанную RSA-SHA256 квитанцию; Android сверяет подпись, ключ, товар, сумму и режим.
Test никогда не выдаёт live-квитанцию. URL успеха сам по себе ничего не включает.

До первого запроса Android сохраняет ключ идемпотентности и случайный 256-битный
секрет восстановления. Повторный запрос после обрыва связи использует тот же счёт.
На сервере хранится только хэш секрета. Закрытие формы не удаляет неоплаченный заказ.
Публичный отпечаток серверного RSA-ключа сверяется с APK до открытия оплаты.

## 1. Инфраструктура и стабильный ключ

Нужны аккаунт Cloudflare с Workers/D1, Node.js 24 и доступ к настройкам этого GitHub
репозитория. Это облачная серверная функция, собственного VPS не требуется.

```sh
cd payments
npm ci
npm test
npm run keys
```

Команда `keys` однократно создаёт RSA 3072:

| Файл | Назначение |
|---|---|
| `.secrets/license-private-key.txt` | Значение GitHub/Worker secret `LICENSE_PRIVATE_KEY`; PKCS8 DER в Base64 |
| `.secrets/license-public-key.txt` | Android `payment.publicKeyBase64`; SPKI DER в Base64, публичное значение |

Скрипт не печатает ключи и отказывается перезаписывать существующие файлы.
Сохраните закрытый ключ в защищённой резервной копии. Не коммитьте `.secrets`,
пароли, `.dev.vars` или токены. Публичный ключ должен сохраняться во всех будущих
версиях APK, даже если новые покупки выключены. Смена ключа требует миграции:
текущая офлайн-лицензия поддерживает один закреплённый ключ.

Создайте D1 базу `diet-diary-payments` в Cloudflare Dashboard или командой:

```sh
npx wrangler login
npx wrangler d1 create diet-diary-payments
```

Сохраните выданный `database_id` (UUID). Выберите постоянный HTTPS origin Worker,
например выданный Cloudflare адрес `diet-diary-payments.<ваш-subdomain>.workers.dev`,
либо собственный домен, уже привязанный к Worker. Не вводите непроверенный домен.
Путь, query, fragment, логин и пароль в базовом URL не допускаются.
Доступность этого адреса нужно проверить из реальных российских сетей и со стороны
Robokassa до live; наличие deployed Worker само по себе её не подтверждает.

## 2. Поля технических настроек Robokassa

`API_ORIGIN` ниже — точный постоянный HTTPS origin созданного Worker, без `/` в конце.
Это не адрес GitHub Pages: статический сайт не принимает серверные уведомления.

| Поле кабинета | Значение |
|---|---|
| Сайт магазина | `https://diet.efreitor2001.ru/` |
| Идентификатор магазина / MerchantLogin | Точное значение созданного магазина; это не его название и не ИНН |
| Алгоритм расчёта хэша | **SHA256**, для тестовых и основных настроек |
| Тестовый Password #1 | Отдельный случайный секрет → `ROBOKASSA_TEST_PASSWORD1` |
| Тестовый Password #2 | Другой случайный секрет → `ROBOKASSA_TEST_PASSWORD2` |
| Основной Password #1 | Отдельный случайный секрет → `ROBOKASSA_PASSWORD1` |
| Основной Password #2 | Другой случайный секрет → `ROBOKASSA_PASSWORD2` |
| Result URL | `API_ORIGIN/robokassa/result` |
| Метод Result URL | **POST** |
| Success URL | `API_ORIGIN/robokassa/success` |
| Метод Success URL | **GET** |
| Fail URL | `API_ORIGIN/robokassa/fail` |
| Метод Fail URL | **GET** |
| Кодировка | **UTF-8** |
| Повторные/рекуррентные платежи | Не используются, не подключать для этой лицензии |
| Оферта | `https://diet.efreitor2001.ru/offer/` |
| Политика | `https://diet.efreitor2001.ru/privacy/` |

Не используйте одинаковые тестовые и основные пароли. Password1 подписывает форму,
Password2 проверяет уведомление и подписывает запрос состояния; не меняйте их местами.
При переходе test → live сохраняйте тестовые secrets, чтобы корректно распознавать
запаздывающие уведомления по старым тестовым заказам. `IsTest` задаётся из режима
сохранённого заказа, а не из параметров, произвольно присланных клиентом.

### ИП на НПД и чек

По оферте лицензиар — ИП Ефремов Сергей Олегович, ИНН 471905964680,
ОГРНИП 326470400141351. В кабинете должны быть его реальные верифицированные реквизиты.
Для ИП на НПД подключение **Робочеков СМЗ** требует обращения в поддержку Robokassa
и разрешения партнёру в «Мой налог». Созданный магазин и переданный `Receipt`
сами по себе этот сервис не включают.

Код передаёт одну позицию, количество 1, сумму 149, `tax=none`,
`payment_method=full_payment`, `payment_object=intellectual_activity`.
Параметр `sno` не передаётся: НПД нельзя подменять значением УСН/ОСН из списка 54-ФЗ.
`tax=none` — «без НДС», а не ставка НДС 0%. Совместимость настроек конкретного
магазина с Робочеками СМЗ нужно подтвердить при подключении и проверить по чеку.

## 3. Переменные и secrets GitHub Actions

В репозитории: **Settings → Secrets and variables → Actions**.

Repository **Variables** (публичные параметры, не secrets):

| Имя | Что ввести |
|---|---|
| `CLOUDFLARE_ACCOUNT_ID` | ID своего аккаунта Cloudflare |
| `PAYMENT_D1_DATABASE_ID` | UUID созданной D1 базы |
| `PAYMENT_API_BASE_URL` | Постоянный HTTPS origin Worker |
| `ROBOKASSA_MERCHANT_LOGIN` | Точный MerchantLogin созданного магазина |

Repository **Secrets**:

| Имя | Что ввести |
|---|---|
| `CLOUDFLARE_API_TOKEN` | Ограниченный своим аккаунтом токен для Worker scripts и D1 (edit); дополнительные права только при управлении custom routes |
| `LICENSE_PRIVATE_KEY` | Содержимое созданного PKCS8 Base64 файла |
| `ROBOKASSA_TEST_PASSWORD1` / `ROBOKASSA_TEST_PASSWORD2` | Два тестовых пароля кабинета |
| `ROBOKASSA_PASSWORD1` / `ROBOKASSA_PASSWORD2` | Два основных пароля кабинета; обязательны для live |

Пароли вводятся в защищённые поля кабинетов. Не присылайте их в issue, PR или чат.
Они не должны попадать в `payment-config.properties`.

Workflow **Deploy Robokassa payment API** запускается вручную из Actions:

1. Первый запуск: `mode=test`, `enable_payments=false`. Он применяет D1 миграции,
   разворачивает API с выключенными новыми покупками, загружает secrets и сохраняет
   выбранный флаг. Push кода не запускает deployment.
2. Проверьте `GET API_ORIGIN/health`, затем сохраните callback URL в Robokassa.
3. Для внутренней тестовой сборки запустите `mode=test`, `enable_payments=true`.
   `/v1/config?store=rustore` должен вернуть `available=true` и отпечаток ключа.
4. После тестового сценария, активации магазина, подключения чеков и проверки
   опубликованных правовых документов включите `mode=live`, `enable_payments=true`.

Workflow намеренно сначала останавливает новые продажи. Если настройка secrets или
последующий шаг не удались, сначала исправьте ошибку в Actions, затем повторите его.
Отключение новых покупок не выключает ResultURL и получение уже оплаченных прав.

## 4. Публичная конфигурация Android

В корне репозитория `payment-config.properties` содержит только:

```properties
payment.enabled=false
payment.apiBaseUrl=
payment.publicKeyBase64=
```

После готовности сервера установите его HTTPS origin, публичный SPKI Base64 ключ и
`payment.enabled=true`. Эти три значения допустимо коммитить, закрытый ключ — нет.
Для локальной/CI сборки можно переопределить их Gradle `-Ppayment.enabled=...`,
`-Ppayment.apiBaseUrl=...`, `-Ppayment.publicKeyBase64=...` или переменными
`DIET_PAYMENT_ENABLED`, `DIET_PAYMENT_API_BASE_URL`, `DIET_PAYMENT_PUBLIC_KEY_BASE64`.

Соберите внутренний debug для test-кассы. Release проверяет live-режим и откажется
открывать тестовый checkout. Для Google Play backend разрешает новую форму только
при доверенной стране `RU`; заголовок клиента или язык телефона это не заменяют.
RuStore и Huawei используют свои варианты `rustore` и `huawei`.

Пакет приложения и прежний ключ подписи сохраняются. Подписывайте обновление
имеющимся ключом владельца; этот репозиторий не создаёт новый release keystore.

## 5. Что проверить перед выпуском

- Успешный test: Robokassa вызывает POST ResultURL, получает `OK<invoice>`, API
  показывает `test_paid`, рекламы за тестовые деньги не отключает.
- Отмена/3-D Secure/возврат из банковского приложения: нет ложного unlock;
  после перезапуска сохраняется возможность проверить тот же заказ.
- Live после активации: конечная цена 149 ₽; настоящий чек НПД; подписанный
  `paid` ответ; прекращение native/app-open рекламы; восстановление через свою
  JSON-копию и Google Drive. Реальная платёжная операция требует участия владельца.
- Задержка уведомления: authenticated GET может подтвердить live через OpStateExt.
  Документация не гарантирует конкретную валютную метку в `OutCurrLabel`; код
  принимает только RUB/RUR и точные 149 ₽. Иной ответ не отключает рекламу без
  подписанного ResultURL: требуется сверка с поддержкой, а не ослабление проверки.
- После восстановления старой копии дневника действующая лицензия не исчезает;
  изменённый вручную JSON или подпись не дают права на отключение рекламы.
- В Google Play вне РФ не предлагается новый Robokassa checkout; уже оплаченная
  лицензия проверяется и восстанавливается. Не создавайте скрытый обход для ревью.
- Страницы privacy RU/EN/ZH и SDK disclosure уже опубликованы по адресам из APK;
  декларации магазинов соответствуют окончательному release, а не только исходникам.

## Данные, восстановление и ограничения

D1 хранит псевдонимные invoice/UUID лицензии, idempotency key, хэш секрета, магазин
приложения, MerchantLogin, режим, сумму/валюту, статус, даты и подписанную квитанцию.
Исходный IP не записывается в D1; инфраструктура получает его, страна используется
для eligibility, хэш IP — для ограничения новых заказов. Запрос eligibility возможен
уже при открытии настроек или раздела покупки в сконфигурированном приложении.
Диета, вес, сон, Google OAuth-токены и резервные копии на платёжный сервер не уходят.
Форма Robokassa собирает необходимые ей данные напрямую. Уведомление/ответ состояния
могут временно пройти через память Worker с email или сведениями платёжного счёта;
эти поля не используются для лицензии и не сохраняются в D1.

Подтверждение лицензии переносится с дневником и **не привязано** к Google-аккаунту.
Не передавайте свой JSON другим людям. Без сохранённого подтверждения и без секрета
незавершённого заказа автоматического поиска покупки по email нет: обращайтесь к
владельцу по контактам оферты. Перенос APK/данных, очистка и uninstall сами по себе
не удаляют платёжные/фискальные записи провайдера. Базу заказов и ключ нужно резервировать.

Офлайн-лицензия бессрочна. Автоматический отзыв после возврата/chargeback и ротация
ключа в текущей версии не реализованы. Возврат оформляется владельцем по оферте;
отзыв права потребует отдельной онлайн-схемы и обновления приложения. D1/Cloudflare
не дают основания заявлять, что все данные физически хранятся в России; применимые
условия обработки/локализации нужно согласовать перед реальным включением.
